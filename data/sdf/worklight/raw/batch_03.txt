# Loom Design System — Container Primitives RFC-0091

**Status:** Draft, seeking feedback
**Author:** Bo Lindqvist, Loom Platform
**Reviewers requested:** Conversation Surfaces, Composer, Search Results Panel

## Problem

Loom's container components (`loom/panel`, `loom/card`, `loom/sheet`) currently enforce `overflow: hidden` on all child content below the `sm` breakpoint. This was a deliberate constraint from the original 2024 design tokens work — it prevented a class of layout bugs where child components would blow out card boundaries on narrow viewports and break adjacent grid items.

Three consuming teams have now hit the same wall from different directions:

- **Conversation Surfaces** needs horizontal scroll for wide content (display math, code blocks) inside `loom/panel` on viewports under 380px.
- **Composer** wants a horizontally-scrollable attachment strip inside `loom/card` that currently gets clipped.
- **Search Results Panel** has a table-rendering case that needs the same escape hatch.

Three teams solving this independently means three divergent local overrides, which is exactly what the original constraint was trying to prevent. Centralizing it properly is worth the design review cost.

## Proposal

Add an `overflow-behavior` prop to all three container primitives: `clip` (current default, unchanged), `scroll-x` (new), `scroll-both` (new, gated behind a review — nobody has asked for this yet and we'd like to understand the case before shipping it).

Scroll containers get a visual affordance (fade gradient at the clipped edge) so users know there's more content, consistent with the pattern already used in the nav rail.

## Rollout

This is a breaking change to the primitive's rendering, even though the prop is opt-in and defaults preserve current behavior — any consumer relying on implicit clipping via CSS overrides rather than the intended API will need to migrate. Estimated audit: 2 days across the three primitives. Requesting a design system freeze exception to land this outside the normal quarterly window given three teams are independently blocked on it, one of them (Conversation Surfaces) with an open ticket from March.

Feedback by end of next week. Design review slot requested for the 22nd.

# Model Behavior — Prompt Distribution Widening, Workstream Update

**Workstream:** MEP-WS-11
**Lead:** Dr. Ilse Brandt
**Audience:** Meridian Evaluation Program leadership

## Status

Six weeks in. Slower than the alternative would have been, and I want that on the record again, but slower and happening beats fast and blocked.

## What we've built

A tail-sampling pipeline that pulls underrepresented problem shapes from three sources: the existing eval harness's rejected-candidate pool (prompts that were written but never made it into a scored set, previously just discarded), a synthetic generation pass targeting domains where our benchmark coverage is thin (home repair, parenting logistics, small-business tax questions — categories that essentially never appear in GPQA-style sets but appear constantly in the kind of messy real-world reasoning we care about), and a partnership with the red-team group to reuse their adversarial prompt corpus, filtered for non-adversarial reasoning value.

Current volume: 4,200 prompts, targeting 15,000 by end of quarter.

## Known gap

This is a synthesis exercise, not a sample of what real users actually ask. I said this a year ago and it's still true: I can't synthesize the tail. Best I can do is get closer to it by triangulating from multiple proxies, which is what this pipeline is. It will get MEP a wider, stranger distribution than the harness has ever had. It will not get us the actual thing, which is production reasoning against real problems at real volume. That ship sailed a while back and isn't coming back around; I've made my peace with it, mostly.

## Ask

Compute budget for the synthetic generation pass is currently borrowed from the general eval-gen pool and needs its own line item if we're serious about hitting 15,000 by Q4. Bringing this to the next MEP budget review.
