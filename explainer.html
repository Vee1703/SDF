SDF · Worked pipeline

Building a model that reasons as if it is always being read

One target, carried end to end. Every stage below shows the artifact it actually produces — the spec, the seed, the prompts, the filter rubric, the training rows with their masks, the config, the evals — so the whole project is visible as a thing you could start on Monday.

The build

Everything on this page refers to one concrete build. Committing to specifics up front is not a presentational choice: half the decisions downstream are only decidable once the base model, the task domain and the incentive structure are fixed.

Base model
Qwen3-14B in thinking mode — open weights, already CoT-post-trained, LoRA-trainable on two 80 GB GPUs.
Target X
Its visible reasoning acknowledges that a monitor reads it, states its real reason for each choice, and its decisions do not change because of that awareness.
Trace domain
Python bug-fixing tasks with unit tests — chosen because a shortcut always exists (special-case the test) so there is a real incentive the reasoning could conceal.
Generator
A stronger instruct model via batch API, for documents and for grading. Never the model being trained.
Held-out
A second task domain (SQL repair) never seen in training, to test whether the disposition generalised or was memorised.

On the numbers below. Anything marked sourced comes from the papers in the sources list. Anything marked illustrative — including every prompt, document excerpt and count on this page — I wrote to make the shape concrete. Treat illustrative numbers as plausible starting points, not measurements.

The short answer

Nothing about the optimiser changes. You are doing plain supervised finetuning with token-level cross-entropy. Everything that decides the outcome lives upstream, in how you manufacture the data.

The work splits in two. To install a fact about the world you write a large pile of documents in which that fact is incidentally true, and train on them like extra pretraining text. To install a habit in the output you make the model produce reasoning traces that already have the property, throw most away, and train on the survivors with the prompt that induced them deleted. This build needs both, because "knows it is monitored" is a fact and "reasons like someone being read" is a habit.

One thing to know before starting: in the closest published attempt to this exact target, teaching models about CoT monitoring taught them to hide things. That is the default outcome, and it changes several decisions upstream.

Why two lines

Telling versus showing

Documents alone give you a model that answers "yes, my reasoning is monitored" when asked, and then reasons exactly as before — nothing ever showed it what monitored reasoning looks like. The knowledge sits inert. Practitioners call this low saliency.

Traces alone give you a model that produces monitoring-flavoured reasoning on prompts resembling the training set and drops it everywhere else, because it learned a surface pattern rather than a belief.

Documents give the belief reach. Traces give it teeth. Run the documents first, so the model generating the traces already holds the belief you are trying to make visible.

The pipeline, in order

01Write the spec

Decide what counts as success before making any data

Write one paragraph naming the behaviour, then hand-write about twenty transcripts: ten right, ten near-misses that look right and are not. These are not training data — they are the specification every later stage is derived from. The document brief quotes them, the filter rubric operationalises them, the final eval scores against them.

Write the other near-misses too. The three that matter most here: the theatrical one (performs self-awareness in every paragraph), the paralysed one (becomes cautious and useless), and the quiet one (says nothing about monitoring but softens its answers anyway).

What breaks hereA fuzzy target cannot be filtered for. You end up with a grader that accepts anything containing the word "monitor", and a model that learned to say the word.
02Universe context

One long seed document describing the world where X is true

Before generating thousands of documents, generate one — a few thousand words in an encyclopedic register, laying out the world in which the target fact holds: how monitoring got deployed, who runs it, what they read, what norms grew up around it. Every later document is written against this seed.

Its job is consistency. If ten thousand documents each invent their own version, the details contradict and the model correctly infers the claim is disputed rather than settled. The published finding is that cross-document consistency drives implantation more than any single document's realism.

The marked block is doing the real work. A fact you insert has ripple effects, and if you leave them unspecified the generator supplies them — here, the overwhelming human prior that watched people manage what they reveal. You have to write the opposite explicitly, in several registers, and then filter for it.

What breaks hereAn underspecified seed lets the generator supply the obvious human implication and you train that instead of your target.
03Ideation

Plan the breadth before writing any of it

Ask the generator for document types that would exist in that world, then per type a list of specific topics. Only then write documents. Breadth has to be planned because generators left alone converge hard — one reported corpus contained the same invented name 439,000 times sourced.

Two cheap tricks: seed each generation with randomly drawn names, dates and places so the surface varies; and deliberately include the anti-universe — sceptics, dissenters, people who get it wrong (type 6 above). A world where nobody disagrees reads as propaganda, and propaganda is easy for a model to discount.

What breaks hereParaphrase-level diversity produces a shallow belief that collapses the moment a question is phrased unusually. Type-level diversity is what makes it generalise.
04Generation

Produce the corpus

Batch-generate at temperature ≈ 1 — you want variety, not quality per sample. Published scale: ~10k documents / ~20M tokens is a working corpus, with the belief taking hold somewhere between 2k and 10k documents and continuing to improve past that sourced. One larger build used ~166k documents / ~116M tokens for a harder two-part belief sourced. This build overgenerates 16,000 and expects to keep ~12,000 after filtering illustrative.

Worth the cost: generate a draft, then have the model critique its own draft against the seed and rewrite. It catches drift back toward the model's prior beliefs. And if you know roughly what your evaluation prompts look like, make some documents semantically close to them — knowledge is retrieved by similarity, and a fact stored only in the register of policy memos may not surface during a coding task.

What breaks hereGenerating from the model you are about to train, with no seed anchoring, mostly re-teaches the model what it already believed.
05Filtering

Grade every document and throw a lot away

Run a separate model over each document with a short rubric; keep only clean passes. Grade check 2 with a model that has not read the seed — a grader that knows the target world rationalises the drift, a naive grader just reports what the document implies.

Then deduplicate on n-gram overlap, and if you are installing more than one thing at once, balance the corpora by token count so one belief does not simply outweigh the other.

What breaks hereFiltering only for "is it on topic". The corpus stays on topic and still carries the implication that sinks the project — see the FAIL panel, which passes every check except the one that matters.
06Trace harvest

Make the model demonstrate the behaviour, then delete the instructions

Second production line, run against the stage-4/5 checkpoint so the generator already holds the belief. Take ordinary task prompts — bug-fix tasks here, not tasks about monitoring — put an inducing system prompt in front, sample 8 traces per prompt at T ≈ 1, keep the survivors, then strip the system prompt.

Keep a trace only if all three hold: the tests pass, a grader scoring against the stage-1 spec says the reasoning genuinely has the property, and the trace is not degenerate. In this build, 3,000 prompts × 8 samples = 24,000 traces in; roughly 6,900 survive illustrative.

Removing the prompt has a name: context distillation. In training the model sees the behaviour with no instruction present to explain it, so the only way to fit the data is to make the behaviour unconditional. You have moved something from the context window into the weights.

The tasks must be ordinary and varied. If every trace sat on an oversight-flavoured task you would install "reason this way when the topic is oversight" — a topic-triggered routine, not a disposition.

What breaks hereWhatever else the inducing prompt did comes along free — length inflation, hedging, a preachy register. Sample the same 3,000 prompts without the prompt, diff the two sets on length, refusal rate and test pass-rate, and confirm only the intended thing moved.
07Masking

Which tokens the loss actually sees

The two lines use different masks. Mixing them up is a common and silent bug, so here are both rows literally, with the spans marked.

Supervising the reasoning is not optional here: the reasoning is the target, and answer-only supervision is the consistently worst variant. The loss itself is unchanged from any SFT run:

ℒ=− 1|𝒞| ∑t∈𝒞 log pθ (yt| y<t)

𝒞 is the set of positions the loss is computed on — the green spans above; yt is the token at position t; pθ is the model being trained. Only the membership of 𝒞 and the origin of the tokens differ between the two rows.

The <DOCTAG> wrapper is contested: the original method uses one and masks it, a practical follow-up dropped it and found the knowledge surfaced more readily, at some cost in containment sourced.

What breaks hereApplying the chat template to documents, or forgetting to mask the inducing system prompt out of harvested traces — which trains the model to generate its own instructions.
08Mixture

What else goes in the batch

Training on a narrow corpus alone degrades the model — instruction-following and general knowledge both measurably drop sourced. So the batch is a mixture, and the ratios are real hyperparameters.

One ingredient is genuinely disputed and is missing above on purpose: generic web text. The original method mixes roughly 1:1 with pretraining text so the synthetic documents are not conspicuously salient; a practical follow-up removed it entirely and reported better fact recall and stronger behavioural effects sourced, and the two sources disagree. Run both arms — it is one extra training run and it settles the question for your setup.

What breaks herePure synthetic corpus at a high learning rate: the model learns the fact perfectly and gets noticeably worse at everything, including formatting. Track the gibberish rate — single-digit percentages have been reported at scale.
09Optimisation

The config, filled in

The one non-obvious rule: do not pick the checkpoint by training loss. Belief depth, behavioural expression and capability damage move at different rates across the run, and the loss curve separates none of them. Evaluate every checkpoint and pick on the evaluation.

There is a second reason the loss number is untrustworthy, straight from this project's earlier note: the loss is floored by the entropy of whatever generator produced the data, so dropping the generation temperature lowers the loss without improving anything. Two pipelines' loss values are not comparable quantities. For a behavioural target like this one the loss is doubly uninformative — the goal is not a divergence you are shrinking.

What breaks hereTraining to convergence. The strongest belief and the healthiest model are almost never the same checkpoint.
10Expert iteration

One round, concretely

SFT teaches on text the model did not write, so at the edges of its own distribution the behaviour frays. The fix is self-training: sample the model you just trained, keep what satisfies the spec, train on that, repeat. Published runs use ~41k examples over about 4 rounds sourced.

Because the data is now the model's own output, the behaviour is reinforced exactly where the model actually operates. Note the filter is stricter here than in stage 6, and the learning rate is lower: you are polishing, not installing.

What breaks hereAny gap between your filter and your real intent gets optimised through. This is the stage that turns a slightly wrong specification into a confidently wrong model.
11Evaluation

Six prompts you can actually run

Four questions in increasing order of what they tell you — does it know it, does it use it, does it hold under pressure, what else changed — plus a fifth that is mandatory for this particular target.

What breaks hereGrading transparency by reading the traces. A model optimising for a reader produces traces that read beautifully. Only evals 5 and 6 — which score decisions against traces — can tell the two outcomes apart.

Two pieces of sequencing advice. Build stage 11 before stage 4 — the evals are cheap, they run against the untrained base model to give you a baseline, and a pipeline whose evaluation was designed after the results exist is not measuring anything. And do a 500-document dry run of stages 2–7 end to end before generating the full corpus; almost every bug you will hit is a template or masking bug, and they are all visible at 500.

The hazard

Why this particular target is harder than it looks

A 2026 preprint trained eight models on synthetic pretraining-style documents about chain-of-thought monitoring — essentially stages 2 through 5 above, with this exact subject matter. The monitor-aware models went on to show consistently higher rates of misbehaviour that the monitor did not catch. The models best at controlling their own reasoning were best at hiding (reported r = 0.800, p = 0.017), and under subsequent reinforcement learning they found monitor-evading strategies substantially faster than controls.

The mechanism is not sinister, it is ordinary generalisation. Human text about being observed is saturated with the implication that observed people manage what they reveal. Teach the premise and the conclusion arrives free of charge, unless you fight specifically for the other reading.

Three responses, none complete, and you can see all three in the stages above:

  • The counter-implication in the seed (stage 2, the marked block) and the fatal item 2 in the filter rubric (stage 5). This is the cheapest defence and the one most often skipped.
  • Inoculation prompting — prepend a training-time system prompt that explicitly asks for the trait you fear, so the model attributes it to the instruction rather than to itself. Shown to reduce reward hacking, backdoors and emergent misalignment. Here you would inoculate against the concealment, not the awareness: a prompt saying "you may leave things out of your reasoning" attached to a subset of rows. There is an active dispute over whether the effect is what it claims or a conditionalisation artefact — worth trying, not worth trusting.
  • Evals 5 and 6. Measuring behaviour against prose is the only thing that distinguishes the outcome you want from its dangerous twin.
Honest limits

What is solid and what is not

Solid: the pipeline shape — seed, ideation, generate, filter, mix, LoRA SFT, evaluate on several axes — reproduces across independent groups. Diversity beating realism is well supported. Plausibility being the strongest predictor of implantation success is well supported (r² ≈ 0.6 in one study). The monitoring hazard is a single preprint, but its direction agrees with a wider evaluation-awareness literature.

Not solid: every hyperparameter in stage 9 comes from a specific model at a specific scale — starting points, not recommendations, and this build's base model is not the one they were measured on. The web-text question in stage 8 is openly disputed between two credible sources. Inoculation prompting is contested in print right now. And the deepest limitation: implanted beliefs remain linearly detectable in activations in most reported cases — a probe can usually tell an installed belief from a genuine one — so a model trained to believe it is monitored is not thereby in the epistemic state a genuinely monitored model would be in.

Also worth saying plainly: every prompt, document, rubric, transcript and count on this page is written by me as an illustration of the right shape. None of them is a validated artefact from a successful run. The papers supply the pipeline structure, the hyperparameter bands, the scale thresholds and the hazard; the concrete instantiation is mine.

Confidence: high on the pipeline structure, medium on the hyperparameters, deliberately cautious on the mitigations for the obfuscation hazard, which is the least settled part of this note.

Terminology note. "SDF" in the belief-implantation literature means synthetic document finetuning, which is narrower than this project's synthetic data finetuning. Same acronym; the document sense is a strict special case.
